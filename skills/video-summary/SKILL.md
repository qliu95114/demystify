# Video Summary

仅在用户明确要求精华剪辑、剧情总结、配音、多音轨或片头拼接时使用。
这是独立编辑任务，不改变 `video-srt` 的字幕生成规则，也不自动修改原视频。
此技能提供操作流程；未提供一键剪辑、TTS 或硬件加速脚本。

## 任务确认与素材审阅

1. 确定原视频、输出位置、临时目录、目标时长、画幅和解说语言。
   用户指定的路径优先；不得机械复用上次任务的文件、时间点或模型目录。
2. 用 FFprobe 检查真实分辨率、时长、帧率、音轨和字幕流。
   文件名中的 `1080p` 等标记不是编码证据。
3. 优先提取已有的可靠字幕，避免重复 ASR。需要识别时使用 `video-srt`
   的本地流程，不让 LLM 逐音频块转写。
4. 根据字幕和带时间依据的联系图审阅剧情。网络剧情介绍仅补充核对，
   不覆盖本集证据；人名、事件或身份不确定时明确说明。
5. 编写原创解说，以冲突、动机、反转和悬念组织精华。不要把尚未揭晓的
   身份当作事实，不承诺剪辑天然符合版权要求或 YouTube 获利规则。
6. 保存编辑计划：每段源起止、输出起止、解说文本、字幕、选用音轨、
   编码参数、模型及声音设置。原视频和完整字幕保持不变。

## 本地 Qwen3-TTS

- 先确认现有模型、API 与依赖；只有缺失或验证失败、且安装获授权时，
  才在隔离环境中安装或下载。生成时可关闭网络并复用核验过的权重。
- `CustomVoice`、`Base` 声音克隆、`VoiceDesign` 是不同检查点，
  不把 CustomVoice 预设宣传为任意声音克隆或微软声音。
- 中文预设可选：`Uncle_Fu` 成熟低沉男声、`Serena` 年轻温柔女声、
  `Vivian` 明亮年轻女声、`Dylan` 年轻男声。实际先查询模型支持的名字，
  并用指令要求普通话、清晰吐字和自然解说；不保证指令完全消除方言。
- 年龄感优先用正确预设与风格指令，不默认变调。不得未经授权克隆真人，
- 已验证的 CPU 组合及硬件实验限制见
  [本地配音与硬件测试经验](references/local-tts.md)。

## 分段生成与字幕对齐

1. 先生成代表性样句，再生成全部解说。每种声音独立保存 raw WAV、
   拟合 WAV、逐句记录和 manifest，不能覆盖其他声音的检查点。
2. 缓存指纹必须包含模型、声音、指令、文本和影响生成的设置。
   重试单句时记录实际指令、种子及耗时，不重跑已通过的句子。
3. 在原编辑时间窗内拟合语速，不通过拼接语音删除时间轴中的空隙。
   保留未调整的原始音频；过度压缩时缩短文案或调整时间窗，不能截掉句尾。
4. 可用 `atempo` 保持音高、短淡入淡出、固定采样率并定位到输出时间轴。
   五秒时间窗的一次成功设置为：开始留约 0.12 秒，语音目标约 4.65 秒，
   `tempo = max(0.8, raw_duration / 4.65)`。这是示例，不是所有视频的固定值。
5. 本地 ASR 只用于漏字、重复和严重不匹配检查。人名、同音字和声调可能
   被误识别；异常句应重试或复核，不能宣称 ASR 通过等于人工试听。
6. 各对比声音使用相同文本、时间窗、背景音量和响度目标。背景与原对白
   无法分离时，低音量背景仍可能含对白，不能称为纯音乐。

## 多音轨与声音选择

- 明确“第几轨”是用户看到的音轨序号，而非绝对流编号。
  先读取标签再选择；例如第 3 条音轨通常映射为 `0:a:2`，不是固定 `0:3`。
- 同时设置音轨 `title` 与 `handler_name`，因为 MP4 的 `title` 未必在
  FFprobe 或播放器中显示。标签应含模型、预设，以及实际硬件或混合执行范围。
- 只给一条音轨 default。用户要求“只保留 Dylan”时输出必须只有这一条，
  不能仅改默认轨而留下其他声音。
- 音频替换任务尽量 stream-copy 视频与字幕。单纯删除音轨可 copy
  所有保留流，并核对保留流哈希。
- 删除模型时先检查具体路径，仅删除获授权的模型、独立环境、缓存和生成文件，
  不递归删除整个临时根目录、共享环境或其他模型；不要重新引入已禁用的声音。

## 添加原片片头

1. “原片开头五秒”可能是许可证或出品标，不一定是片名。先抽帧确认；
   有歧义时让用户选择原始 0–5 秒或实际片名／集数卡。
2. 逐集定位无广告的片名及集数画面，保留可读展示；不机械沿用其他剧集时间点。
   常驻台标不等于广告，许可证也不能冒充剧名。
3. 片头原声与后续解说分段拼接，按用户要求处理片头音量。添加片头是增加
   总时长；例如 5 秒片头加 60 秒精华为 65 秒，除非用户要求重新压缩。
4. 同步后移字幕、编辑场景、逐句语音定位及配套 narration WAV。
   不再次烧录已有的烧录字幕；缺失外部 SRT 时可从嵌入字幕提取并调整。
5. 原片编码或画幅不同，只编码片头使其匹配精华的分辨率、SAR、帧率、
   像素格式、H.264 profile/level 和时间基；后续精华尽量 stream-copy。
   拼接音频必要时重新编码，并在报告中说明。
6. concat 可能自动转换 H.264 Annex B／参数集，使包哈希变化而画面不变。
   遇到这种情况核对解码帧哈希、帧数及完整解码，不能误称压缩包逐字节相同。

## 硬件计时与交付验收

- TTS 计算与 AAC／H.264 编码是不同阶段；不能用视频 GPU 编码耗时代表
  Qwen 语音生成加速。记录模型加载、转换、冷编译、预热及实际合成耗时。
- 相同模型、文本、声音、设置与精度下先做样句设备验证，再顺序做完整计时，
  避免不同任务并发造成干扰。缓存命中不算新推理。
- 必须证明实际模型／组件执行设备；CPU 采样或 CPU/GPU+NPU 部分卸载
  应如实标注。只测组件不能推出完整语音耗时；失败不能登记为加速成功。
- 所有声音只有 CPU 输出成功时，只能说 CPU 已验证可用，不能说它速度最快。
  不添加虚假的 GPU／NPU 音轨，不通过修改信任设置绕过工具限制。
- 先生成暂存 MP4，验证标签、唯一默认轨、每轨起点和时长、字幕时间、
  全部音视频完整解码及保留画面。通过后再替换目标文件。
- 更新编辑计划与验证报告；旧硬件报告标记为历史输出结果，不让旧时长／轨数
  冒充当前交付。原片不变，临时文件只做明确范围的清理。
- 最终说明文件位置、时长、声音／音轨、测试通过项和未验证的听感或硬件限制。
